# FileFlow application audit and repair — October 22, 2026

The existing React/TypeScript PWA, native Java/XML Android app and Spring Boot worker were inspected and repaired incrementally. Branding, navigation and the existing optional Supabase work were preserved. No production deployment, live credential change, paid service, database or cloud infrastructure was introduced. Local test tools were installed inside the ignored `.tools` directory.

This is a repair and verification record, not a declaration that the application is ready for Google Play. **Fixed** below refers to the specific source defect and stated verification, not certification of every feature on every device. Component reports contain more granular findings; overlapping reports must not be added together as unique issues.

## Actual architecture and operating cost

| Operation | Current execution | Cost/architecture decision |
| --- | --- | --- |
| Image conversion/compression, Image to PDF, scanner, Prepare for Upload | Browser/device | Keep local and account-free |
| PDF merge/split/rotate/reorder/delete | Browser/device | Keep local; native limits need low-memory device measurement |
| PDF table extraction | Java worker | Tabula is technically portable to Android but would need a separately tested port; no new service added |
| Excel export | Worker on web; local ZIP/XML on Android | Native text-first export already avoids an extra server request |
| PDF compression | Java worker | Potential Android PDFBox port, subject to memory/quality testing; current worker reused |
| PDF to Word | Worker | Editable reconstruction not currently local; existing adapter retained; no paid replacement approved |
| Word to PDF | LibreOffice worker | Real renderer required by current implementation |
| OCR | Unsupported | Tesseract is a possible self-hosted/on-device option, but rasterization, language data, memory and table recognition require separate integration/benchmarking |
| Accounts/storage | Optional web Supabase; no document database | Basic tools remain available without login. Anonymous rate limits are not JWT authorization |

See [hosting decision](hosting-options.md) for current provider policy sources. A temporary local Cloudflare Quick Tunnel is the verified no-account/no-card development approach, not a production uptime solution. Render Free is a conditional demonstration candidate with memory/sleep restrictions and possible account verification. Current Hugging Face Docker Space creation requires a paid plan, so it is not presented as a no-card free solution. No host was provisioned.

## Final execution addendum

Backend final `mvn package` passed on the repaired source: **23 tests, zero failures/errors/skips**, runnable55,969,879-byte JAR at `server/target/fileflow-processing-0.2.0.jar`. The packaged YAML was inspected to confirm the corrected `pdf2docx.main` command. The final log is `server/target/audit-package-release.log` (ignored build output).

The packaged worker was started on loopback with a512MiB Java heap and the tested local Python environment. `scripts/verify-processing.mjs` completed **13 PASS, zero FAIL, one UNVERIFIED**. Real PDF-to-Word returned a37,086-byte DOCX containing both source identifiers. Real extraction recovered all six checked cells; XLSX reopened with `001234` and `12345678901234567890` intact, and opted-in number/date cells were correctly typed. A1,066-byte already-small PDF returned unchanged1,066 bytes with a truthful false reduction flag. All500 blank pages were accepted without invented data;501 pages were rejected. Scans, malformed PDFs, malformed review data and an unapproved origin failed explicitly. The unverified conversion is Word-to-PDF: LibreOffice is not installed, so the service returned503 and the script did not count a conversion pass. Capability health correctly listed PDF-to-Word, table extraction and PDF compression while reporting overall degraded status.

After these requests, an inspection found **zero `fileflow-job-*` directories** in the configured local worker temporary root. This verifies cleanup for those completed samples only, not abrupt shutdown, host snapshots or all filesystem failures. Both default and desktop-linux Docker probes failed; the latter was repeated with approved read access and confirmed that the Docker Linux engine pipe does not exist. Container/LibreOffice/qpdf integration remains blocked.

`node scripts/verify-native-xlsx.mjs` passed using the actual compiled Android `OfficeOpenXml` class through the JDK. An independent ExcelJS reader verified two valid worksheets, leading zeros, a 20-digit identifier, literal formula-like text and embedded tab/newline preservation. This verifies the native pure-Java export bytes without claiming any device UI, codec or SAF behavior.

The original HTTP verification initially exposed incorrect expected400 versus domain422 statuses in the new test script; its expectations were corrected to the API contract. It also exposed the real missing-module engine command defect, which was fixed and then passed actual CLI/HTTP checks.
