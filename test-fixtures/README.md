# Document quality suite

The current PDF-to-Word layout suite is generated by `scripts/pdf-word-fixtures.py`: a CV, multi-page prose with running matter, independent columns, a ruled table with an image, and typography/Unicode samples. `scripts/pdf-word-quality.mjs` converts them with the selected Git baseline or working browser engine. `scripts/render-word-quality.ps1` uses locally installed Microsoft Word; `scripts/inspect-word-quality.py --assert` checks actual renderings and writes comparison images and a local slider report. Generated and private inputs stay under ignored `.tools/pdf-word-quality/`; do not commit customer files. See [measured results and repeatable commands](../docs/pdf-to-word-accuracy.md).

The automated suite generates synthetic, non-sensitive fixtures in code so opaque user documents are not committed. `server/src/test/java/com/fileflow/server/service/ProcessingQualityTest.java` creates:

- an image-heavy PDF with selectable text;
- a ruled financial-style table PDF with text and numeric cells;
- a multipage English/Urdu DOCX with a formatted title, colors and sizes, merged table, two images, header, footer, and page-number field.

The browser E2E suite generates PDFs/DOCX/images and validates downloaded PDF, XLSX, ZIP, JPEG, scanner, page editing, and responsive flows.
